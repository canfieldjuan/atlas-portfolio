# Plan: Sync Tailwind lockfile to 4.3.2

## Why this slice exists

Dependabot opened a Tailwind bump, but after the companion
`@tailwindcss/postcss` update landed, this branch still carried stale nested
`tailwindcss@4.2.4` lockfile entries under Tailwind's PostCSS/compiler packages.
That meant the app could continue resolving the old compiler path even though the
root Tailwind package was on `4.3.2`.

## Scope (this PR)

Slice phase: Production hardening

1. Regenerate the npm lockfile so Tailwind's root package and Tailwind's
   PostCSS/compiler dependencies resolve consistently to `4.3.2`.
2. Remove stale nested `tailwindcss@4.2.4` entries from the lockfile.
3. Add this plan doc for the dependency lockfile correction.

### Files touched

- `web/package-lock.json` - regenerate the Tailwind dependency graph.
- `web/plans/PR-Dependabot-Tailwindcss-4-3-2.md` - this plan doc.

## Mechanism

Running `npm --prefix web install --package-lock-only` against the updated
manifest graph removes the redundant nested `tailwindcss@4.2.4` packages under
`@tailwindcss/node` and `@tailwindcss/postcss`. The app still loads Tailwind
through `@tailwindcss/postcss`; the lockfile now makes that path resolve the same
`4.3.2` compiler family as the root package.

## Intentional

- This is a lockfile-only sync after the companion PostCSS package bump; no app
  code or CSS source changes.
- Optional platform package metadata is generated by npm as part of the same
  lockfile normalization.

## Deferred

- None.

Parked hardening: none.
